# 学号身份认证改造计划

## 目标

新用户通过四川大学统一认证完成一次性身份校验，随后使用“学号 + 川流课栈密码”登录。学校密码、验证码和学校 Token 不写入数据库、缓存或日志。

## 用户流程

1. 注册页填写学号、川大统一认证密码、课栈密码并同意协议。
2. 后端调用可替换的川大身份校验器；只有校验成功且返回的账号与提交学号一致时才创建用户。
3. 用户表保存加密学号、学号盲索引、校验时间和课栈密码哈希。
4. 后续默认使用学号和课栈密码登录，不再访问学校认证系统。
5. 当前没有存量用户，不保留手机号或短信认证入口。

## 技术边界

- `UniversityIdentityVerifier` 隔离外部认证协议与业务服务。
- SCU-CLI 适配器不得通过命令行参数传密码，使用伪终端输入，并为每次校验创建独立配置目录，完成后销毁。
- SCU-CLI 适配器默认关闭；生产环境必须显式配置可执行文件和内存临时目录。
- 开发环境可显式启用 mock 校验器，生产环境禁止 mock。
- 认证错误对外区分“凭据错误”和“校验服务不可用”，不返回上游响应正文。
- 学号仅以哈希形式进入限流键和审计明细。

## 纵向实施

1. 数据库：删除用户手机号字段，新增 `university_id_lookup` 唯一索引和 `university_verified_at`。
2. 后端：移除手机号和短信认证服务，新增校验器、学号注册服务、学号登录请求与限流。
3. 前端：移除短信登录，默认学号登录；注册表单增加学校密码和独立课栈密码。
4. 测试：覆盖迁移、校验器选择、注册成功/失败、重复学号、学号登录、旧手机号登录和表单交互。

## 上线条件

- 明确 SCU-CLI 的 AGPL-3.0 合规方案并提供对应源码地址。
- 在隔离测试账号上完成真实统一认证联调。
- 部署环境中的运行目录为内存文件系统，并限制 API 进程读取权限。
- 完成隐私政策更新，明确一次性处理学校账号凭据的目的和保存期限。
