## 1. 目标

在首年总预算 `¥400` 内，采购一套可支撑川流课栈 MVP 上线试运行的云资源方案。

约束条件：

- 以省钱为第一目标
- 优先选择中国大陆可用、购买门槛低的方案
- 以当前代码真实依赖为准，不按旧版多机生产架构采购
- 默认采用单机部署

当前 MVP 组件范围：

- 保留：`Nuxt 3`、`FastAPI`、`PostgreSQL`、`Redis`、`Celery`、`对象存储`
- 暂缓：`Elasticsearch`
- 暂缓：`OnlyOffice`
- 不采购：`独立 RDS`、`独立 Redis`、`CDN`、`SLB`

## 2. 结论

推荐采购主方案：

- 云服务器：阿里云轻量应用服务器 `2C2G / 40-50GB SSD / 3-4Mbps`
- 对象存储：腾讯云 COS
- 域名：任选 1 个 `.cn` 或 `.com`
- HTTPS：Let's Encrypt

推荐理由：

- 轻量服务器活动价通常比标准 ECS 更容易压进预算
- 腾讯云 COS 新用户免费额度更适合早期校园项目
- 单机可以直接承载当前 MVP 所需服务，运维复杂度最低

### 3.3 购买建议

购买阿里云轻量服务器时，优先筛选：

- 地域：优先成都、广州、上海、杭州，其次北京、深圳
- 套餐：优先 `2C2G`
- 带宽：至少 `3Mbps`
- 系统盘：至少 `40GB`
- 周期：优先 `1 年`

不建议购买低于以下配置的机器：

- `1C1G`
- 带宽仅 `1Mbps`
- 系统盘低于 `40GB`

原因：

- 后端、前端、PostgreSQL、Redis、Celery 同机部署后，`1C1G` 容易在构建和迁移阶段就吃满资源
- 带宽过低会显著影响上传下载体验
- 系统盘过小会挤压 Docker 镜像、数据库和日志空间

## 4. 备选方案

### 4.1 备选 A：腾讯云轻量 + 腾讯云 COS

适用情况：

- 团队成员有校园认证
- 当期腾讯云轻量活动价优于阿里云

采购项：

| 类别 | 推荐产品 | 推荐规格 | 预估费用 |
|---|---|---|---|
| 云服务器 | 腾讯云 Lighthouse | `2C2G / 40-50GB SSD / 3-4Mbps / 年付` | `¥150-300` 或活动价 |
| 对象存储 | 腾讯云 COS | 标准存储，新用户免费额度优先 | `¥0-50` |
| 域名 | 腾讯云 / 其他 | `.cn` 或 `.com` 1 个 | `¥30-85` |
| **合计** |  |  | **约 `¥180-435 / 年`** |

官方链接：

- 腾讯云轻量应用服务器：<https://cloud.tencent.com/product/lighthouse>
- 腾讯云校园活动：<https://cloud.tencent.com/act/campus>

备注：

- 如果是公开价而不是校园价，这个方案有一定概率略超 `¥400`

### 4.2 备选 B：单机本地盘 + 对象存储仅备份

适用情况：

- 服务器活动价好，但对象存储暂时不想接入
- 需要进一步压缩早期账单

特点：

- 上传文件先落服务器本地盘
- COS/OSS 只做每日备份

不推荐长期使用，原因：

- 与当前对象存储直传思路不一致
- 后续迁移成本更高
- 单机磁盘损坏风险更高

## 5. 不采购项

以下资源不应在当前预算阶段采购：

- 独立 RDS PostgreSQL
- 独立 Redis 实例
- Elasticsearch 独立节点
- OnlyOffice 专用机器
- CDN
- SLB
- 多机高可用集群

原因：

- 当前预算无法支撑
- 现阶段用户规模不足以证明这些资源的必要性
- 先上线再按真实流量扩容，比先堆正式生产架构更合理

## 6. 采购后部署边界

采购完成后，默认部署形态如下：

- `Nginx`
- `Nuxt 3`
- `FastAPI`
- `PostgreSQL`
- `Redis`
- `Celery Worker`

全部运行在同一台服务器上，通过 Docker Compose 管理。

对象存储用途：

- 用户上传文件
- 缩略图
- 后续静态衍生资源

MVP 不启用：

- `Elasticsearch`
- `OnlyOffice`

## 7. 风险与控制措施

### 7.1 流量费用风险

风险：

- 对象存储外网下载费用会在资料下载增多后上升

控制措施：

- 开启每日下载次数限制
- 限制单文件大小
- 优先压缩图片和缩略图

### 7.2 单机稳定性风险

风险：

- 单机故障会导致整站不可用

控制措施：

- 每日自动备份数据库
- 上传文件放对象存储，不只存在本地
- 记录镜像版本和部署步骤，便于重建

### 7.3 搜索体验风险

风险：

- 不上 Elasticsearch 时，全局搜索能力弱于理想方案

控制措施：

- MVP 阶段先接受基础搜索能力
- 当资料量和搜索投诉明显增多后，再升级 Elasticsearch

## 8. 最终采购清单

按优先级排序，建议直接这样买：

1. 阿里云轻量应用服务器 `2C2G / 40-50GB SSD / 3-4Mbps / 1年`
2. 腾讯云 COS 存储桶 1 个
3. 域名 1 个

如主方案买不到活动价，则切换为：

1. 腾讯云轻量应用服务器 `2C2G / 40-50GB SSD / 3-4Mbps / 1年`
2. 腾讯云 COS 存储桶 1 个
3. 域名 1 个

## 9. 一句话决策

当前最合适的采购方案是：

**买 1 台阿里云轻量服务器，再配 1 个腾讯云 COS 存储桶，其余高成本组件全部延后。**
